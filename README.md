# 파메어스 플랫폼기획팀 주간보고 v1.4.0

GitHub Pages에서 동작하고 Google Sheets를 데이터 저장소로 사용하는 서버리스 주간보고 도구입니다.

## v1.4.0 핵심 변경

이번 버전의 핵심은 **동시편집 안전성**입니다.

기존 버전은 자동저장 시 브라우저가 가진 전체 데이터를 Google Sheets에 다시 기록했기 때문에, 여러 사용자가 동시에 수정하면 먼저 저장된 다른 사용자의 내용이 오래된 화면 상태로 덮어써질 수 있었습니다.

v1.4.0부터는 다음 방식으로 변경됩니다.

- 전체 시트 초기화 / 전체 재작성 로직 제거
- 수정한 필드만 Google Sheets에 PATCH 방식으로 저장
- 신규 작업은 신규 행만 append
- 삭제한 작업은 해당 행만 실제 삭제
- 드래그앤드롭은 해당 그룹의 순서 필드만 저장
- KPI 수정은 해당 KPI의 실적 또는 비고만 저장
- 프로젝트명 변경은 해당 프로젝트 작업들의 `project` 필드만 저장
- 저장 직전 Google Sheets의 현재 값을 다시 확인하여 동시 수정 충돌 감지
- 같은 필드를 다른 사용자가 먼저 수정한 경우 덮어쓰기 전 확인창 표시
- 삭제 대상이 다른 사용자에 의해 최근 수정된 경우 삭제 전 재확인
- 화면이 유휴 상태일 때 약 20초 간격으로 다른 사용자의 최신 변경을 자동 반영

## 현재 접속자 / 편집 중 표시

Google 실연동 모드에서는 `접속현황` 시트를 사용합니다.

- 브라우저 탭별 `session_id` 생성
- 현재 사용자 이메일 기록
- 현재 보고 주차 기록
- 작업명 / 상세 / 완료예정일 / KPI 등 현재 포커스를 가진 필드 기록
- 약 45초마다 heartbeat 갱신
- 마지막 heartbeat가 2분 이상 지난 세션은 비활성으로 판단
- 화면 상단에 `접속 N명` 표시
- 다른 사용자가 같은 칸을 편집 중이면 해당 입력칸을 파란 외곽선으로 강조
- 마우스를 올리면 편집 중인 사용자 이메일 확인 가능

기존 Google Sheet에 `접속현황` 시트가 없어도 v1.4.0이 처음 연결될 때 자동 생성합니다. 새 원본 양식에는 해당 시트가 기본 포함되어 있습니다.

## 자동저장 방식

텍스트 입력 도중에는 Google API를 호출하지 않습니다.

- 작업명 / 상세 / 완료예정일 입력 중: 저장 안 함
- 입력칸에서 벗어날 때: 변경된 필드만 저장
- KPI 비고 입력 중: 저장 안 함
- KPI 비고에서 벗어날 때: 비고 셀만 저장
- KPI 숫자 변경 확정: 해당 실적 셀만 저장
- 프로젝트 / 작업 추가·삭제: 필요한 행만 추가·삭제
- 드래그앤드롭: 순서 필드만 저장
- 새 주차 생성: 주차 행과 이월되는 신규 작업 행만 추가

저장 완료 시 우측 하단에 아래 형식의 토스트를 표시합니다.

```text
[26-08-20 17:48:00 저장되었습니다.]
```

## 충돌 처리

사용자 A와 사용자 B가 같은 셀을 동시에 수정한 경우:

1. 각 사용자가 편집을 시작한 시점의 값을 기준값으로 기억합니다.
2. 저장 직전 Google Sheets의 현재 값을 다시 읽습니다.
3. Google Sheets 값이 기준값과 달라졌다면 다른 사용자가 먼저 수정한 것으로 판단합니다.
4. 현재 원격값과 내 값을 보여주고 내 값으로 덮어쓸지 확인합니다.
5. 취소하면 원격값을 유지합니다.

서로 다른 필드를 수정하는 경우에는 충돌하지 않습니다. 예를 들어 한 사용자가 `상세`를 수정하고 다른 사용자가 같은 작업의 `완료/예정일`을 수정하면 두 변경이 모두 보존됩니다.

## 파일 구성

- `index.html` : 화면 구조
- `styles.css` : UI 스타일
- `app.js` : 주간보고, Google Sheets, 동시편집/증분저장 엔진
- `config.js` : Google OAuth Client ID / Spreadsheet ID
- `seed-data.js` : 데모 데이터
- `xlsx-export.js` : 월별 성과 엑셀 출력
- `파메어스_주간보고_GoogleSheets_원본양식_v1.4.xlsx` : 신규 Google Sheets 원본
- `배포_및_Google연동_매뉴얼.html` / `.md` : 배포 가이드

## GitHub 기존 사이트 업데이트

기존 실운영 사이트의 `config.js`에는 Google Client ID와 Spreadsheet ID가 들어 있으므로 **덮어쓰지 마세요.**

업데이트 시 기본적으로 다음 파일을 교체합니다.

```text
index.html
app.js
styles.css
README.md
```

`접속현황` 시트는 웹 앱이 자동 생성하므로 기존 Google Sheet 자체를 새 파일로 교체할 필요는 없습니다.

커밋 후 GitHub Pages 배포가 완료되면 브라우저에서 `Ctrl + F5`로 캐시를 갱신하고 화면 상단의 `v1.4.0`을 확인합니다.

## 주의사항

- `접속현황` 시트는 시스템 관리용이므로 직접 수정하지 않는 것을 권장합니다.
- Google Sheets에서 사용자가 직접 행을 삭제하거나 ID를 변경하면 웹 화면과 연결이 끊길 수 있습니다.
- `task_id`, `kpi_id`, `decision_id`, `week_id`는 고유 식별자이므로 변경하지 마세요.
- 동시편집 충돌 감지는 웹 앱을 통한 편집을 기준으로 합니다. Google Sheets에서 셀을 직접 수정한 경우에도 저장 직전 값 비교로 충돌을 감지할 수 있습니다.
